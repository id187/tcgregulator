# TCG REGULATOR

플레이: [https://id187.github.io/tcgregulator/](https://id187.github.io/tcgregulator/)

DAY 0 긴급 투입부터 DAY 500 결산까지 카드 발매와 금제를 운영하는 로컬 싱글플레이 TCG 메타 시뮬레이터입니다.

## 현재 구현 범위

- 전체 테마 150개, 시작 활성 테마 5개, 시작 활성 유저 10,000명
- 테마마다 14장의 카드가 준비되며 최초 5장, 지원마다 3장씩 실제 카드풀에 추가(최대 3회)
- DAY 0 긴급 투입 직후 분포를 확인하고 첫 금제를 즉시 결정하며, DAY 0~7 동안 탭이 순차 개방되는 사건형 인수인계
- 취임 전 14일의 추정 그래프를 참고 자료로 제공하고, 실제 티어·분포 판정에는 최근 7일의 기록을 집계
- 1일 단위 결정론적 메타 시뮬레이션
- DAY 10부터 20일마다 제품 검토(DAY 10·30·50·70·90·110…)를 진행
- 일반 팩은 9개 시안에서 신테마·지원·범용 카드를 각각 1장 이상 포함해 4장을 선택하고, 각 시안을 7단계(-3~+3)로 파워 조정
- 매 3번째 제품 검토(DAY 50·110·170…)는 일반 팩과 분리된 재판 팩으로 진행하며, 출시 30일 이상 된 카드 9개 후보에서 파워 조정 없이 3장을 선택
- 30일마다 지원 제안 1회, 다음 일반 팩 시안에 제안한 구테마 지원 보장
- DAY 0부터 40일마다 금제위원회 개최(DAY 0·40·80·120…·440, DAY 450 최종 발매 후 DAY 500 결산)
- 금제와 출시의 효과를 추적해 결정 D+9에 공식 리포트로 전달하며, 기존 점수 변화 요약 안에서 시장의 종합 반응과 선택으로 형성 중인 운영 노선을 짧게 암시
- DAY 1부터 `월 1.45억 + 활성 유저당 2,500원`을 30일로 나눈 운영비가 매일 정산
- 기존 `대표 세트 초판 증산`을 `통합 대회 플랫폼 구축`(공인 플레이 인프라)으로 교체하고, 시즌 전면 개편·해외판 동시 론칭과 함께 임기 1회만 선택하는 고위험 성장 프로젝트로 제공
- `시즌 전면 개편` 성공 시 시즌 2 경계를 실제로 기록하고 메타 피로·상위권 연속 기록 등 시즌 경쟁 지표를 초기화하되 누적 운영 기록은 보존
- 기존 `재판 캠페인` 액션은 카드 공급과 겹치지 않는 `매장 덱 대여·교환망`으로 개편하고, 카드 재판은 전용 재판 팩에서만 처리
- 프로젝트 집행 당시 환경·신뢰·최근 발매·금제 품질을 고정해 성공 확률과 성공·실패 커뮤니티 반응을 판정
- 파츠별 허용 매수 0~3장 조정
- 하루 20개씩 생성되는 날짜별 커뮤니티 게시글
- 테마 체급·지원 강도·구카드 교체율·금제 기간·해제 후 실제 성적을 교차한 상황별 반응
- 발매·금제 효과는 공표 다음 날부터 반영되고, 금제 후 3일간 관련 여론이 집중됨
- 점유율·승률·불쾌도·피로도·유저층·매출 변화
- 플레이 중 실제 분포·시세·금제·발매 결과가 조건을 만족할 때 `몰락했던 테마의 부활`·`고가 카드 시장 스캔들`·`실패한 금제의 역사적 참사`·`별명이 붙은 망가진 팩`·`사랑과 증오의 대표 테마` 서사가 커뮤니티에서 사후적으로 발생
- 최종 운영자금과 환경 안정률, 캠페인 전체의 누적 운영 기록을 교차한 9개 엔딩
- 최고 엔딩은 평균 환경·신뢰, 건강한 환경 유지율, 장기 독주, 금제·발매 이력을 함께 반영하며, 부족했던 방향은 결산 화면에서 다음 임기 힌트로 제공
- 금제 강도·변경 없음·출력 조정·재판·사업 선택의 누적으로 운영 노선을 판정하고 결산에서 행정부의 정체성으로 기록
- 중간 사건의 2택 결정 결과와 금제·발매 확인 및 리포트 도착을 단계별 애니메이션으로 연출
- 검은 연꽃 운영 AI `L.O.T.U.S.`의 탭별 상황 안내
- WebView2 고정 로컬 주소의 `localStorage` 자동 저장, 연속 스키마 마이그레이션 및 호환 불가 원문 비파괴 보존

## 개발 실행

Node.js `>=22.13.0`이 필요합니다.

```bash
npm install
npm run dev
```

Vite가 표시하는 로컬 주소에서 개발 화면을 확인합니다.

## 검증

```bash
npm run lint
npm test
npm run analyze:balance -- --seeds=100
```

`npm test`는 정적 프로덕션 빌드와 엔진·저장 스키마·일일 커뮤니티 테스트에 더해 실제 렌더링·클릭 기반 핵심 UI 테스트를 실행합니다. `analyze:balance`는 금제 과잉·금제 없음·최대 출력·보수적 출시·수익 우선·신뢰 우선 봇을 지정한 수의 시드에서 실제 reducer로 완주시키고 엔딩 빈도와 평균 지표를 표와 JSON으로 출력합니다.

## Windows 빌드

DEV 폴더에서 다음 스크립트를 실행하면 `web/dist`를 갱신하고 DEV 바로 아래의 로컬 실행용 EXE를 다시 만듭니다.

```powershell
.\build-windows.ps1
```

실행 시 Node.js나 로컬 서버는 필요하지 않습니다. DEV의 `TCG REGULATOR.exe`가 `web/dist`의 정적 파일을 WebView2로 직접 엽니다. 실행 PC에는 .NET 9 Desktop Runtime과 Microsoft Edge WebView2 Runtime이 필요합니다. 이 빌드는 형제 `TCG REGULATOR-GIT` 폴더를 읽거나 수정하지 않습니다.

## GitHub Pages 준비

형제 `TCG REGULATOR-GIT`은 EXE 배포 폴더가 아니라 별도의 웹게임 저장소 준비본입니다.

```powershell
.\sync-web-git.ps1 -Apply
```

이 명령은 웹 원본과 GitHub Actions 워크플로만 복사하며 `.git`, `node_modules`, `dist`, EXE는 복사하지 않습니다. 저장소와 원격 주소는 자동으로 만들지 않습니다.

## itch.io HTML5 업로드

```bash
npm run build
```

`dist` 폴더 자체가 아니라 그 안의 `index.html`과 `assets`가 ZIP 최상위에 오도록 압축해 업로드합니다. itch.io 프로젝트는 `HTML Game`으로 만들고 다음 설정을 권장합니다.

- 실행 방식: `Click to launch in fullscreen`
- Fullscreen Button: 켜기
- Scrollbars: 끄기
- Mobile Friendly: 실제 모바일 터치 QA 뒤에만 켜기

게임 화면은 iframe과 전체 화면의 가변 뷰포트에 맞춰집니다. 고정 임베드를 쓸 때도 별도 페이지 스크롤 대신 각 게임 패널 내부에서 스크롤되도록 구성되어 있습니다.

## 구조

- `app/game/content.ts`: 150개 테마와 2,100개 준비 파츠
- `app/game/engine.ts`: 순수 reducer 기반 일일 시뮬레이션
- `app/game/administration-profile.ts`: 플레이 선택 기록 기반 운영 노선 판정
- `app/game/save-migrations.ts`: 순차 저장 스키마 마이그레이션
- `app/game/types.ts`: 직렬화 가능한 상태와 명령 타입
- `app/page.tsx`: 화면 상태와 게임 명령을 연결하는 UI 조정 계층
- `tests/`: 엔진·저장·커뮤니티 검증
